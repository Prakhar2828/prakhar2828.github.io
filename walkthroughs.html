  1. Open the public project

    This is the public Asteria mission-operations app, with its mission overview, FlightStack and MissionOps workspaces. The recording starts before initialization; no spacecraft telemetry is claimed while the app is offline.

  2. Initialize the C++ model

    Initialize mission starts the browser C++ model with seed 42. The initial model is in BOOT with 82% battery charge. These are synthetic spacecraft values, not real mission telemetry.

  3. Send an acknowledged command

    In MissionOps, BOOT is transmitted and acknowledged. The command audit and onboard event timeline record the result. A request alone is not treated as evidence of success.

    In FlightStack, the lab undervoltage control sets battery charge to 15%. The C++ model enters SAFE. Fault injection is a lab control, not a spacecraft radio command.

    Back in MissionOps, RECOVER is rejected with FR-08_RECOVERY. The source is still active and battery charge is below the recovery threshold. The clip shows the refusal and audit record; it does not show a completed recovery.

A2 MissionLab
One mission. Traceable reasoning.

A continuous recording of the public mission explorer, moving between lunar approach, pericynthion, return corrections and splashdown.

Try the recorded interface ↗Read the case study ↗Inspect the source ↗

Independent public-data reconstruction. Geometry, source-reported events and engineering models remain distinct; no private Orion telemetry or targeting solution is represented.

Read the full walkthrough & engineering decisions

  1. Align the mission clock

    The shared clock aligns public trajectory products, source-reported events and engineering context. Selecting lunar approach changes the geometry and explanatory panel together.

    Inspect recorded state 1 ↗

  2. Inspect the closest approach

    At pericynthion, the explorer presents the derived 8,281.938 km Moon-center distance and 6,544.538 km lunar altitude. These describe different reference surfaces; the case study preserves that distinction.

    Inspect recorded state 2 ↗

  3. Follow the return

    The return-corrections milestone connects the public mission story with its geometry. Separate engineering controls model how an impulse affects arrival; a public scalar burn magnitude does not disclose the flown direction vector.

    Inspect recorded state 3 ↗

  4. Connect the mission to its outcome

    Splashdown closes the public mission timeline. The site carries the same evidence policy into reconstructed entry geometry, bounded heating models and postflight reporting: every quantity retains its source or model class.

03 / RECORDED NOVEMBER 16, 2026 / 24 SECONDS

Wind VISION
Run it. Compare it. Inspect it.

A continuous recording of the browser reconstruction explorer using two actual held-out synthetic examples from the public release.

Try the recorded interface ↗Read the case study ↗Inspect the source ↗

Two synthetic examples, one velocity component and fixed sensor geometry. Per-field scores are distinct from the full 872-field evaluation. This browser example performs classical reconstruction, not neural inference or a weather forecast.

Read the full walkthrough & engineering decisions

  1. Reconstruct from observations

    The estimated-mean plus four-neighbor IDW estimator receives 40 complete observed sensor histories and geometry weights. On field 2, it predicts 15,360 hidden values with RMSE 0.690580 m/s. Hidden truth is accessed only for evaluation.

    Inspect recorded state 1 ↗

  2. Compare a simpler transfer rule

    Switching to direct IDW uses the same observations and evaluation values. Field 2 RMSE rises to 1.852057 m/s. The comparison makes the effect of the estimated height profile visible instead of attributing the result to a neural model.

    Inspect recorded state 2 ↗

  3. Check another held-out example

    Field 948 uses the same locked sensor split. Estimated-mean plus IDW produces RMSE 0.667103 m/s. These two example scores match the Python baseline calculation; they do not replace the aggregate evaluation.

    Inspect recorded state 3 ↗

  4. Inspect the time histories

    Changing the selected hidden sensor compares the reconstructed curve against synthetic simulator truth at that location. The downloadable release separately replays all eight methods across 872 fields, three classical baselines and seven bootstrap intervals.

    Inspect recorded state 4 ↗
